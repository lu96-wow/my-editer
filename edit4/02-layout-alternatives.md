# edit4 · 02 布局：功能 / 原理 / 实现选项比对

> 目的：在继续写之前，把「布局必须提供什么」「必须满足什么不变量」「还有哪些实现路线」
> 摊开比对，确认当前取舍，并列出值得实验的替代。

---

## 1. 功能清单（布局必须提供什么）

### 1.1 结构
- 把一块矩形递归切给 N 个 pane（guillotine）。
- 任意嵌套（2×2、三列、侧栏+主区+状态栏）。
- 增：把一个 pane 分裂成两个。
- 删：摘掉一个 pane，容器收拢到只剩一个孩子。
- 贴边：在整棵树的一侧插入一块（区域：侧栏/状态栏）。

### 1.2 尺寸
- 每段有**硬最小尺寸**。
- 区分**固定**与**弹性**。
- 容器 resize：弹性项吸收/吐出（且不改比例）。
- 拖缝：改相邻两段。
- 拖交点/整条线：同时改多条缝。

### 1.3 几何查询
- `layout : tree × area → 矩形(id→rect) + 缝(cuts)`
- `hit : 点 → pane | cut | (cut cut)`
- 方向导航：`neighbor : id × dir → id`（**当前缺**）
- `ids / path-of / node-at / node-min`

### 1.4 覆盖层
- 浮窗：anchor + size → rect，不参与切分。

### 1.5 性能/工程
- 纯函数、确定、可测。
- 输入不变 → 结果恒等（可缓存）。
- 状态可规范化（可序列化/比较）。

## 2. 原理与不变量

| 不变量 | 含义 |
|---|---|
| I1 尺寸守恒 | `Σ child 长度 + (k-1)*gutter = extent` |
| I2 min 硬底 | 任何解出的长度 `≥ min`（不足时按 min 溢出，不压塌） |
| I3 比例不漂 | 纯容器缩放时，弹性项两两之比恒定 |
| I4 局部精确 | 拖缝只改相邻两段的尺寸意图，其余项**一格不动** |
| I5 结构稳定 | 改尺寸不改变树结构；改结构不影响其它子树尺寸意图 |
| I6 确定性 | 无浮点、无哈希序依赖，同输入同输出 |
| I7 投影性 | 几何 = `f(tree, floats, size)`，不依赖焦点/文本/插件 |
| I8 幂等/规范 | 规范化后重复求解 = 恒等 |

其中 I3 与 I4 是一对张力：局部精确要求"只动两项"，比例不漂要求"整体等比"。
解法：**容器缩放按当前尺寸等比分配** ⇒ 两个都不破。

## 3. 实现选项（按维度）

### 3.1 尺寸的表示

| 代号 | 表示 | 拖缝精确 | resize 比例 | 备注 |
|---|---|---|---|---|
| S1 | 绝对尺寸 + grow/shrink 权重（CSS flexbox / 旧 edit3） | 是 | **漂**（多余按权重分） | 被否 |
| S2 | 绝对尺寸，缩放时按当前尺寸等比（**现方案**） | 是 | 不漂 | basis 兼任比例 |
| S3 | 显式比例权重 + 固定绝对项 | 是（重量在两段间转移） | 不漂 | 表示天然规范 |
| S4 | 约束系统（min/max/preferred 一起解） | 是 | 可控 | 重、难确定 |
| S5 | 只存首选尺寸，比例另存 | — | — | 过定，冗余 |

**关键洞察**：S2 与 S3 数学等价（都相当于按比例缩放），差别只是"比例"是显式归一化
（权重）还是隐式（绝对尺寸 + 等比缩放）。i3 用的是 S3（`percent` 为浮点）。

### 3.2 结构

| 代号 | 结构 | 缝语义 | 代价 |
|---|---|---|---|
| T1 | **n 叉 split 树**（现方案） | "一行/一列并排"，缝=连续线 | — |
| T2 | 二叉 split 树 | 中列被拆成两层，缝碎成多段 | 交点/整线要特判 |
| T3 | 网格（col/row/span） | 共享边影响多格 | 任意嵌套难、一致性难 |
| T4 | 显式矩形 + 邻接表 | 无结构 | resize 后不变量全靠维护 |
| T5 | BSP（任意轴切割） | 最一般 | n 叉 T1 已是 BSP 的"同轴合并" |

### 3.3 分隔缝

| 代号 | 方式 | 优点 | 缺点 |
|---|---|---|---|
| G1 | **预留 `n-1` 格 gutter**（现方案） | 缝独立、交点/整线自然、不压内容 | 每层扣 1 格 |
| G2 | 画在窗边上（edit2 原子格） | 不额外占格 | 边界归属、共享边抑制复杂 |
| G3 | 不留缝 | 简单 | 无法拖 |

### 3.4 求解与取整

| 代号 | 取整 | 性质 |
|---|---|---|
| R1 | **最大余数**（现方案） | 确定、无偏；但内容变化时哪项多拿 1 格可能翻转 |
| R2 | 累计进位（carry） | 跨 resize 连续、不抖；需存每项余数 |
| R3 | floor + 余数全给最后一项（旧 edit3） | 有偏、依赖顺序 |
| R4 | 四舍五入 | 可能不平（和 ≠ extent） |

### 3.5 min 的处理

| 代号 | 做法 | 性质 |
|---|---|---|
| M1 | **硬夹 + 按比例回收，命中 min 的段冻结后重分**（现方案，`distribute` 的蓄水） | 正确、仍尽量保比例 |
| M2 | 只在拖拽代码 clamp（旧 edit3） | 会挤塌，被否 |
| M3 | 软约束（可低于 min） | 不满足硬不变量 |

### 3.6 规范化（settle）

| 代号 | 做法 | 何时跑 | 收益 |
|---|---|---|---|
| N1 | 不规范化，纯投影 + 缓存 | — | 简单；每次 cache miss 重解 |
| N2 | **resize 时 settle**（现方案） | 每个容器尺寸变 | 之后全走快路径；状态规范 |
| N3 | 每次尺寸编辑都 settle | 每个拖拽帧 | 更多分配 |
| N4 | 把解出尺寸存在独立 memo（不改树） | — | 树保持"意图"，但规范表示在别处 |
| N5 | 用显式权重（S3） | 无需 settle | 权重本身即规范表示 |

### 3.7 缓存 / 增量

| 代号 | 做法 | 失效键 | 备注 |
|---|---|---|---|
| C1 | 不算缓存，每帧重算 | — | 旧 edit3 的问题 |
| C2 | **按身份 `eq?` + size**（现方案） | (tiling, size) | 持久化结构天然 O(1) 判定 |
| C3 | 显式版本号 | version | 序列化/克隆时更稳 |
| C4 | 两级（平铺 / 浮窗） | 分开 | 拖浮窗不重解平铺 |
| C5 | 沿路径增量重解 | path | n 小时收益低 |

### 3.8 命中与拖拽

| 代号 | 做法 | 性质 |
|---|---|---|
| H1 | **缝=全局直线（cut）**（现方案） | 普通缝/十字/T/整线统一 |
| H2 | 每段缝一个 handle + 交点特判（旧 edit3） | 特例补丁 |
| H3 | 每窗四边 handle（edit2） | 边界归属复杂 |

### 3.9 浮窗

| 代号 | 做法 |
|---|---|
| F1 | **独立覆盖层**（现方案）：anchor + size，z=顺序 |
| F2 | 进布局树（当叶子） | 参与切分，不适合菜单/弹层 |
| F3 | 第二层求解器（可锚 pane / 可锚浮窗） | 更一般，复杂度上升 |

### 3.10 导航 / 查询

| 代号 | 做法 |
|---|---|
| Q1 | 树遍历（sibling walk）取方向邻居 |
| Q2 | **几何查询**：按矩形找方向最近邻（可含浮窗） |
| Q3 | 维护邻接表 | 一致性成本高 |

## 4. 总比对（与现方案相比）

| 维度 | 现方案 | 主要替代 | 现方案胜在 | 替代可能更好 |
|---|---|---|---|---|
| 尺寸 | S2 绝对+等比 | S1 flexbox | 比例不漂 | — |
| 尺寸 | S2 | S3 显式权重 | basis 直观、整数精确 | 表示规范、无需 settle |
| 结构 | T1 n 叉 | T2 二叉 | 缝/整线语义 | 手术实现更少代码 |
| 分隔 | G1 gutter | G2 边 | 交点/整线自然 | 省 1 格 |
| 取整 | R1 最大余数 | R2 carry | 无状态 | 跨 resize 不抖 |
| min | M1 蓄水 | — | 硬底 + 尽量保比 | — |
| 规范 | N2 settle | N5 权重 | 树=已解布局 | 无需额外步骤 |
| 缓存 | C2+C4 | C5 增量 | 简单、够快 | 大 n 时更省 |
| 拖拽 | H1 cut | — | 四态统一 | — |
| 浮窗 | F1 独立 | F3 二层 | 简单 | 能锚浮窗 |

## 5. 现方案的短板（诚实列出）

1. **`flex` 数值无意义**：现在只是"固定/弹性"标记，字段名却叫权重。要么改名
   `fixed?`，要么走 S3 把权重移到 `basis`（或新字段）。
2. **比例"不漂"仍在整格里抖动**：最大余数在内容变化时可能让某项 ±1 格跳变。
   真·连续需要 R2（carry），或 S3 的浮点权重（i3 做法）。
3. **min 命中时比例必然破**：任何模型都如此；但我们没定义"破之后如何恢复"。
4. **settle 与缓存都在动状态/身份**：两个机制都在"什么时候失效"上做文章，值得
   统一成一条明确的规则（输入变 → settle? → 缓存）。
5. **没有方向导航**：布局层缺 `neighbor`，命令层要自己做空间查询。
6. **没有不变量自检**：可加 `validate : tree → (listof error)`，在测试里跑。
7. **gutter 只能每 split 配**：若要做"无边框分区"等，需更灵活。

---

## 6. 值得实验的替代（按性价比）

1. **把 `flex` 语义改清楚**（改名或移到权重）。
   - 最小改动、最大可读性提升。
2. **R2 累计进位求解器**：
   - 给每段存一个 carry（余数），分配时带上，跨 resize 连续、不跳 1 格。
   - 与"比例不漂"是同一诉求的加强版。
3. **S3 显式权重表示**：
   - 让"比例"成为一等公民，天然规范（可能免 settle）。
   - 代价：整数归一化 + min 处理。
4. **几何查询做方向导航**：
   - `neighbor` 直接吃 geometry，命令层不再自己算。
5. **`validate` 自检**：
   - 在测试/开发期跑：Σ长度、min、无重叠、cuts 一致。
6. **C5 增量重解（仅当 n 很大）**：
   - 沿 path 只重解受影响的 split；小 n 不划算。

---

## 7. 已决定（本轮）

- **必须保留**：`basis`（局部精确）、min 硬不变量、cut（缝即线）、n 叉、缓存。
- **已采纳**：`flex` 数值 → 布尔 `elastic?`（固定/弹性语义明确）。
- **已采纳**：加 `neighbor`（几何方向导航）、`validate`（不变量自检）。
- **已放弃**：R2 累计进位（整数 ±1 是固有，且无系统性漂移，不值得引入每项余数状态）。
- **仍开放**：S3 显式权重（表示规范化，可能免 settle）、C5 增量重解（大 n 才值）、
  F3 浮窗锚浮窗。
